设备树学习懒人包-方便查阅

May 24, 2026 · 3 min

如果你了解linux原始的驱动编写，你就会明白，设备树只是一个更优、更便捷的数据结构，如果把设备信息写成.c的结构体，那么每次修改都要编译内核，内核里边也有一堆.c文件，它们都是内核外围的，很臃肿。

所以在学设备树之前，一定要建立这样一个思想，我写设备树跟写C结构体描述设备是在做同一件事情，这样的话，你可能就不会很疑惑，比如：设备树是在干什么，设备树里一堆搞不清楚怎么来的名字是怎么回事，内核是怎么获取的这些东西，最终又是怎么成功驱动设备的。

简单来说dtb就是描述设备信息的文本，内核里边有个查找函数来查想要的信息，然后给驱动程序。就一个复杂版二叉树，dtb就是把二叉树遍历一遍，也就是flatten扁平化，然后给uboot和内核使用。

dts语法#

node#

node有以下三种形式，带label的方便其他node引用，&label则是引用。类似C语言的变量名与取变量地址，还有一个特殊的根节点是/。

node_name {

}

label: node_name@address {

}

&label {

}

&label可以用来补充被引用的node

property#

除了node_name还有它的起始地址外，它还包含了很多属性，用来补充node信息。

  1. compatible

    compatible = "manufacturer,model";
compatible = "arm,cortex-a7";
compatible = "fsl,imx6ull-gpmi-nand", "fsl,imx6ull-gpmi-nand";

    compatible需要设备树跟驱动模块能够匹配。命名一般都有现成的。

  2. device_type

    device_type = "cpu";

  3. cells

    #address-cells = <>
#size-cells = <>
#interrupt-cells = <>

    cells的单位是32位，0指的是0x32位,1指的是1x32位,2指的是2x32位，这几个常用。 address-cells指的是地址是多少位的。 size-cells指的是最大需要用多少位数来表示，没大小就是0，1代表u32，2代表u64。 interrupt也一样。

  4. reg

    reg = <address, size>

    对应#address-cells和#size-cells的值。address是起始地址，size是大小。可以去手册的Memory Maps这个章节查看，一般reg配置看这里就行了。

  5. ranges

    ranges = <child-bus-address parent-bus-address length> / <empty>;

    对应#address-cells和#size-cells的值。 ranges用于总线地址映射，就是把子总线地址翻译到父总线地址，一个地址翻译表。子节点里的reg地址，不一定是cpu看到的物理地址，需要经过ranges翻译。

  6. phandle

    phandle = <1>;

    phandle跟label的作用一样，label需要&label来引用，但phandle不行，它必须是独一无二的，不能跟别的一样，应用的时候需要引用对应数字。

    interrupt-parent = <1>;
interrupt-parent = <&label>;

  7. status

    status = "okay"/"disable"/"fail"/"fail-ass";

    用于指示设备的状态

  8. interrupt and mapping(important)

    interrupt-controller;
#interrupt-cells = <1>;


interrupt-parent = <&label>;
