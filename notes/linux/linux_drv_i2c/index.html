Linux 驱动开发｜ I2C驱动 + I2C Bus + I2C<->IIO设备

June 22, 2026 · 2 min

简介#

这个驱动是ap3216c的驱动，它是一个环境光，红外，距离，传感器。在linux下属于IIO设备，因此这个芯片驱动 主要是I2C驱动的注册，i2c设备的匹配，然后在probe时，申请iio设备，将iio设备挂到i2c设备的通用设备的驱动数据下，然后是regmap芯片配置和数据读取。

可以参考内核驱动目录下的一些驱动程序，比如js1212.c

还可以参考中文linux kernel文档工业I/O设备

官方的内核文档实现细节很少，

设备树#

&i2c1 {
    ap3216c@1e {

            >;
        };
    };
};

I2C 驱动#

struct ap3216c_data
{
    struct i2c_client *client;
    struct regmap *regmap;
    struct mutex lock;
};

i2c_driver 的注册比较简单，很少内容，就是of_device_id, i2c_device_id, struct i2c_driver.

在4.1.15版本下，i2c_driver的匹配路径不完全支持设备树，大致是它会串到非设备树下。

因此，需要同时写of_device_id, i2c_device_id。然后才能probe。不写i2c_device_id的话，insmod会不进probe，在match阶段就找不到设备。

然后module_i2c_driver。

regmap#

regmap_config#

regmap_config 它主要描述的是设备的寄存器是多少位的， 值是多少位的，有多少个寄存器，要不要缓存，哪些寄存器不易变，可以缓存。

static const struct regmap_config ap3216c_regmap_config = {
    .reg_bits = 8,
    .val_bits = 8,
    .max_register = ,
    .cache_type = REGCACHE_RBTREE,
    .volatile_reg = ap3216c_is_volatile_reg,
};

剩余的内容就需要去写完整的芯片操作函数，比如通过regmap_read 读传感器数据， 读中断位，regmap_write配置传感器寄存器，这个就是真正的驱动的内容了，不管是裸机，RTOS，还是Linux，都一样。

iio设备#

iio_info#

iio_info 是在sysfs提供接口函数

read_raw函数会根据chan_spec提供不同类型，不同通道，以及事件描述，等等信息，来提供很多文件比如xxx_raw,xxx_scale。

通过读文件，就可以间接调用我们的read_raw函数。

static const struct iio_info ap3216c_info = {
    .driver_module = THIS_MODULE,
    .read_raw = ,
    .read_event_value = ,
    .read_event_config = ,
};

iio_chan_spec#

iio_chan_spec会在probe时设置为iio_dev的channels成员。

它描述了该iio_设备有什么类型的传感器数据，每个类型有几个通道，有没有scale，offset等参数，有没有事件。

static const struct iio_chan_spec ap3216c_channels[] = {
    {
        .type = IIO_LIGHT,
        .channel = 0,
        .info_mask_separate = BIT(IIO_CHAN_INFO_RAW),
        .event_spec = ap3216c_events,
        .num_event_spec = ARRAY_SIZE(ap3216c_events),
    }
    ......
};

iio_event_spec#

该结构体主要用于在中断函数中，我们通过iio_push_event上报了中断事件，我们中断事件的类型，其是大于还是小于阈值，也就是dir方向。

至于后边的mask_separate没搞懂后边宏是啥用法,只知道IIO_EV_INFO_VALUE,可以给sysfs提供一个events目录，目录下可以read/write value。

static const struct iio_event_spec ap3216c_events[] = {
    {
        .type = IIO_EV_TYPE_THRESH,
        .dir = IIO_EV_DIR_RISING,
        .mask_separate = BIT(IIO_EV_INFO_VALUE) | BIT(IIO_EV_INFO_ENABLE),
    },
    {
        .type = IIO_EV_TYPE_THRESH,
        .dir = IIO_EV_DIR_FALLING,
        .mask_separate = BIT(IIO_EV_INFO_VALUE) | BIT(IIO_EV_INFO_ENABLE),
    },
};

iio设备的probe流程#

首先通过devm_iio_device_alloc函数申请一块iio内存，并其后跟着申请一块ap3216c_data大小的内存空间。

indio_dev = devm_iio_device_alloc(&client->dev, sizeof(*data));

然后把iio_dev的内存空间里的多申请的那块空间的指针给到我们的 struct ap3216c_data *data.

data = iio_priv(indio_dev);

然后通过i2c_set_clientdata函数将iio_dev挂到client的dev的drvier_data上

i2c_set_clientdata(client, indio_dev);

再把i2c_client挂到ap3216c_data的client下。

data->client = client;

需要中断就申请中断

regmap的初始化与绑定i2c

data->regmap = devm_regmap_init_i2c(client, &ap3216c_regmap_config);

然后设置iio设备的iio_info,name,modes,iio_chan_spec,num_chan.

indio_dev->info = ;
indio_dev->name = ;
indio_dev->modes = ;
indio_dev->channels = ;
indio_dev->num_channels = ;
indio_dev->dev.parent = ;

调用ap3216c_hw_init,这里是芯片的复位，还有寄存器的设置。

最后

devm_iio_device_register(&client->dev, indio_dev);
